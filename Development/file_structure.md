Development (We keep files that are not part of the project but are about the project.)
    file_structure.md (Keeps the file structures.)
    workspace_rules.md (Our rules are written here.)
    project_summary.md (Short summary of the whole project: architecture, vault format, run flow, token saving, pitfalls. Read it before changing the project, see CLAUDE.md.)
Project (We keep the project source files here. When we hand the project to someone else, we send this folder.)
    CMakeLists.txt (CMake build definition. Core is a static library, the app links it. No third party libraries besides the WebView2 SDK files. Web/* and the WebView2 loader become RCDATA resources through a generated Build/embedded_web.rc. -DBURROW_BUILD_TESTS=ON also builds core_selftest.)
    Build (CMake/Ninja output, not tracked by git.)
    Third_Party (Code we did not write.)
        Web_View2 (Microsoft WebView2 SDK pieces: Include/WebView2.h headers, Bin/WebView2Loader.dll which is embedded in the exe, LICENSE.txt.)
    Web (The web interface, compiled into the exe; plain HTML/CSS/ES modules, no build step.)
        index.html (Page skeleton.)
        app.css (Whole design: colours, layout, components, mascot animations.)
        app.js (Shell: sidebar, top bar with usage gauges, page routing.)
        api.js (Bridge to the program: call(cmd, args) and on(event); WebView2 inside the window, HTTP with an invite token for friends in a browser.)
        i18n.js (Interface language: reads vault.ini's language from the program at load (top-level await), exports tr(text, vars), lang, locale.)
        i18n_en.js (English texts; key = the Turkish text used in the code.)
        state.js (Latest snapshot and lookups.)
        ui.js (Element builder h(), icons, modal, confirm, toast, formatting.)
        forms.js (Generic editor dialog.)
        master_detail.js (List + detail layout shared by tasks, skills, rules, projects.)
        vault_picker.js (Dialog to open / add / create a vault; locked on the first start without a vault.)
        agent_actions.js (Start chat, run a task, agent editor, delete agent.)
        mascot.js (SVG mascots, port of the old drawing code.)
        markdown.js (Small escaping Markdown renderer for agent answers.)
        pages (One module per tab.)
            overview.js, agents.js, chats.js, projects.js, tasks.js, skills.js, rules.js, runs.js (also the live job list and retry), settings.js (language, run limits, vault token budget)
    Resources (Windows resource files.)
        burrow.rc (Manifest resource and version info.)
        burrow.manifest (Windows 10/11 compatibility and per-monitor DPI awareness.)
    Tests (Self tests.)
        core_selftest.cpp (Offline checks of the core and of the process layer; with --live it also runs real Claude Code requests: usage gate, runner, agent-to-agent chat, cancel.)
    Source (All C++ sources.)
        Core (UI independent logic.)
            text.h (String helpers on UTF-8 std::string: trim, split, format, number parsing, UTF-8 length, case-insensitive compare.)
            platform.h/.cpp (Files, folders, time zone aware time and UTF-8 <-> UTF-16 on Windows; the only place that touches std::filesystem and the path APIs.)
            id_util.h/.cpp (Display name -> file-name-safe id.)
            json.h/.cpp (Small JSON reader/writer for stream-json output and conversation logs.)
            markdown_file.h/.cpp (Reads/writes "---" header + body markdown files.)
            agent_definition.h/.cpp (Agent: identity, mascot, boss, model, skills, wake-ups, persona. Also Wakeup, hierarchy helpers.)
            remote_config.h/.cpp (Friends' invites (id, role viewer/editor, token, name) in %APPDATA%\burrow\remote.ini, and `RemoteRoleAllows`: which bridge commands a role may use.)
            telegram_config.h/.cpp (Telegram bot token, chat id, failure-notice switch, receive switch and receiving agent in %APPDATA%urrow	elegram.ini.)
            task_definition.h/.cpp (Task: name, model, priority, minimum remaining usage, instructions.)
            skill_definition.h/.cpp (Skill: instructions + tools + optional MCP config an agent can be given.)
            skill_templates.h/.cpp (Skill templates built into the program; the default ones are copied into every new vault.)
            skill_templates_en.cpp (English name/description/body of each template by id; `LocalizedSkill`.)
            vault.h/.cpp (A vault folder: create, open, load/save/delete agents, tasks, skills, rules, projects.)
            vault_registry.h/.cpp (List of known vaults and the last opened one, stored in %APPDATA%\burrow\vaults.ini; takes over the old otomation folder's list once.)
            usage_info.h/.cpp (Remaining Claude usage (5 hour / 7 day) read from rate_limit_event messages.)
            claude_process.h/.cpp (One `claude -p` child process (Win32 CreateProcess, job object to kill the whole tree): prompt in via stdin from a helper thread, stream-json lines out, polled.)
            run_manager.h/.cpp (Job queue: priority order, usage gate, concurrency limit, usage probe, run records, cancel. The owner calls Tick() about every 120 ms.)
            run_stats.h/.cpp (Per-agent token/run counts for today and the last 7 days from run records; daily limit check.)
            run_record.h/.cpp (One finished run as Runs/<id>.md.)
            job_builder.h/.cpp (Builds the lean system prompt and tool list for chats, tasks and agent messages; parses <send> blocks.)
            conversation.h/.cpp (Conversation files, Conversations/<id>.jsonl.)
            conversation_router.h/.cpp (Stores answers, forwards <send> blocks, hands results back along the job's reply stack: user -> A -> B, B's result goes to A, A's report goes to the user's chat. Limited by kMaxAgentHops.)
            project_definition.h/.cpp (Project: name, summary, notes; ProjectNote is a RuleDefinition. Token estimate.)
            rule_definition.h/.cpp (Company rule: a prompt added to every agent's system prompt, with a token estimate.)
            scheduler.h/.cpp (Decides which wake-ups are due.)
        Ui (Windows: the main window, the web host and the bridge to the page.)
            burrow_app.cpp (WinMain: command line (--vault <folder>, --page <name>), opens the last vault, runs the message loop.)
            folder_dialog.h/.cpp (The Windows folder picker, used by the vault commands.)
            remote_server.h/.cpp (Loopback-only HTTP server for friends: embedded web files, POST /api with an invite token, long poll for changes. Runs commands through a callback to the UI thread.)
            tunnel.h/.cpp (Starts cloudflared as a quick tunnel to the remote server and reports its public address; downloads cloudflared on request.)
            telegram_client.h/.cpp (Telegram Bot API over WinHTTP: send a message, find the chat id, long-poll new messages.)
            web_frame.h/.cpp (The main Win32 window: owns vault data, run manager, scheduler and their timers; builds the snapshot pushed to the page. Works without a vault until one is opened.)
            web_api.cpp (Bridge commands the page can send: chats, runs, save/delete of agents, tasks, skills, rules, projects, notes, vaults.)
            web_view_host.h/.cpp (WebView2 wrapper: creates the control, serves the embedded files from https://app.burrow/, passes JSON messages.)
            embedded_web.h/.cpp (Finds the files compiled into the exe; BURROW_WEB_DIR reads them from disk instead for development.)
            web_json.h (Short helpers for building/reading bridge JSON.)

Vault layout on disk (created by the application, not part of the source tree):
    <vault>/vault.ini (Vault name, format version, language, run limits, default model, token budget.)
    <vault>/Agents/<agent_id>.md (One file per agent.)
    <vault>/Tasks/<task_id>.md (One file per task.)
    <vault>/Skills/<skill_id>.md (One file per skill.)
    <vault>/Rules/<rule_id>.md (One file per company rule; enabled rules go into every agent's prompt.)
    <vault>/Projects/<project_id>/project.md (Project name and summary.)
    <vault>/Projects/<project_id>/Notes/<note_id>.md (Project notes: persistent memory read by every agent working in the project.)
    <vault>/Conversations/<conversation_id>.jsonl (One file per chat or agent-to-agent conversation.)
    <vault>/Runs/<run_id>.md (One record per Claude Code run.)
